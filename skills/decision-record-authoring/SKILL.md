# 决策记录写入

**状态**：enabled
**消费者**：架构师（CC）+ 执行端（通过 `DS-common.md` 引用）
**来源**：dsh `.agents/notes/` 制度；本框架 `decisions/` 于 2026-08-21 建立
**核心判断**：将来有人想把这个决定改回去时，他需要的信息现在在不在？

## 何时用

**触发**：改动触及行为、架构、跨文件约定、流程、工具、测试策略、持久 / 线协议 / 配置格式；或者你正在推翻一条已有的约定。

**不触发**：机械改动（重命名、格式化、纯补测试）；只影响单个函数内部实现且外部无感知的改动。

## 判定：这次要不要写记录

用闭集判，不靠感觉判「非平凡」：

| 命中任一即需要记录 |
|---|
| 改变了对外可观察的行为 |
| 改变了跨文件 / 跨角色的约定 |
| 改变了流程（谁在什么时候做什么） |
| 改变了工具链、门禁或测试策略 |
| 改变了会被持久化的格式（落盘、线协议、配置） |
| 你**推翻了**一条已有的决定 |
| 你能想出一个明白人会提出的反对意见 |

一条都不命中 → 不写。**不要为了显得严谨而攒记录**——记录多到没人读，等于没有。

## 判断程序

### 1. 先做取代检查（写入时，不是事后）

在写新记录之前，先查已有记录里有没有被这次改动推翻的。有 → **同一轮**把旧的状态改成 `已取代` 并写明被谁取代。

事后审计不管用：它永远排在别的事后面。

### 2. 事实与决策分开对待

- **事实**（路径、命令、数量、当前状态）：过时了**就地改对**，不追加「原先是 X」
- **决策**（当初为什么这么定）：**不改写**。要改就写新记录，把旧的标 `已取代`

读者需要知道两件不同的事：现在算什么，以及当初为什么这么定。混在一起，两个都读不出来。

### 3. 写「为什么」，而不是「改了什么」

改了什么 `git log` 里有。记录要回答的是 **`git log` 回答不了的那部分**：当时还有哪些选择，为什么没选。

好的「为什么」能让读者在不重走踩坑过程的情况下，判断这个决定在他的新情况下还成不成立。

### 4. 备选方案：记录，不是编造

`## 备选方案` 写**当时真实考虑过并放弃的**选项，每条附**放弃的代价**。

没有真实备选就写「无备选：<为什么这件事没有第二种做法>」。

⚠️ **不要为了填满小节而发明选项。** 编造的备选比空着更坏——它会让后来者以为某条路已经被论证过了，从而不再考虑它。

### 5. 验收证据

记录里要写清这个决定**怎么被验证是落地了的**：哪条命令、哪个负测试、哪处实证。没有证据的那部分，明写「未验证」。

### 6. 决策记录不是自动否决

已有记录是**讨论的依据**，不是「这条讨论过了所以不许再提」。再提案是允许的，但它必须**击败已记录的理由**——正面回应当时放弃某个选项的那个代价，而不是绕过它重新提一遍。

## 只保留还在阻止诱人错误的记录

一条 `已否决` 的记录，只在**输掉的那个提案仍然是个诱人错误**时才留着：

> 它有正当的推理路径，下一个人会独立地重新提出来，而反驳它需要现场没有的信息。

不满足就删掉。dsh 的原话是 `Keep it only while its rationale prevents a tempting, meaningful mistake; otherwise delete the complete triplet.`

## 归档

归档后**永久冻结**：不可编辑、不可改格式、不可移动删除，不可作当前权威。

**归档内容必须免除演进中的门禁**——用今天的格式去卡昨天冻结的文件，只会逼人修改冻结件，冻结就名存实亡了。

## 停止条件

- 写不出真实的备选 → 先想清楚，或诚实写「无备选」并给理由。不要编
- 发现这次改动其实推翻了一条你没读过的记录 → 停下来先读完再写
- 记录写到需要解释「我们曾经怎么想」才说得通 → 那部分属于讨论轨迹，不进正文

## 本框架的落点

`decisions/`，制度见 `decisions/README.md`，门禁 `scripts/check-decisions.sh`。项目侧的任务文件只留指针，不作为框架决策的权威源。
