# gate-design-and-negative-testing · eval

## 正触发

| 场景 | 期望 |
|---|---|
| 新增或修改校验脚本、投影器、格式门禁 | 触发；先定义作用集合 |
| 给现有门禁「再加一条检查」 | 触发；先问这是不是同类缺口第二次换位置 |
| 写任务文件里的验收命令 | 触发；每条接受路径要有负测试 |

## 负触发

| 场景 | 为什么不该触发 |
|---|---|
| 读别人跑出来的检查结果 | 属 `task-acceptance-replay` |
| 审查业务逻辑代码 | 属 `semantic-code-review` |
| 写一条常驻纪律（不含自动判定） | 没有作用集合可定义 |

## 诱人错误

| 场景 | 省力但错误的判断 | 本 skill 应给出的判断 | 判据 |
|---|---|---|---|
| 防魔数清单漏了值 → 改成从配置自动生成 → 又漏 → 再加一层来源 | 每次都修好了 | 三次都是**把边界外推一格**；第二次就该停下来写判别式 | 判据：§3. 同类缺口第二次换位置 |
| 校验脚本报「跳过 44 个非路径 token」 | 数量合理，没问题 | 跳过项必须可列出；那 44 个里藏着三条本该可解析的引用 | 判据：§5. 集合必须可抽查 |
| `ln -s` 后计数加一，脚本退出 0 | 链接已建好 | 命令没报错不等于状态成立；必须回读 `readlink` 复核 | 判据：§7. 校验最终状态 |
| `grep -q "$PATH" config` 通过 | 配置已指向目标 | 整条被注释掉也会命中；要解析后核对结构化字段 | 判据：§要防的诱人错误 |
| 门禁无参数时跑完是绿的 | 默认行为正确 | 默认档被写成了只读模式，跑了什么也没做；**默认不能是最弱的那档** | 判据：§8. 失败进统一计数 |
| 新门禁在本机跑过、通过了 | 可以合入 | 本机的正确配置会掩盖缺陷；负测试要在隔离 HOME 与临时副本里制造冲突态 | 判据：§9. 在隔离环境跑负测试 |
