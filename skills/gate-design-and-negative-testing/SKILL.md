# 门禁设计与负测试

**状态**：enabled
**消费者**：共享
**投影**：DS-common.md
**来源**：本框架自身门禁的四次实测失效 + sim process-note 0004 / 0007 / 0009 / 0010
**核心判断**：这条门禁**作用在哪些对象上**？新出现的同类对象会自动落进来，还是要有人记得去加？

**本 skill 是判据，不是完整清单。** 一条有实据的阻断胜过一串细枝末节。判据的**由来与实测事故**不在正文里，在下方「判据来源」的记录里——正文只留可执行的检查。

## 跨角色必读

写任何**自动判定通过/不通过**的东西时（测试、校验脚本、格式检查、防魔数清单）：

### 1. 先定义作用集合，再写规则

门禁 = **一条规则 + 它作用的对象集合**。集合才是最容易悄悄缩小的地方。

**收敛判据**：

> **新增一个此前没有的同类对象时，它是自动落入守护范围，还是需要有人记得去加？需要人记得 ⇒ 边界没定义好。**

### 2. 同类缺口第二次换位置：换修法

| 第几次 | 处置 |
|---|---|
| 第一次 | 正常修 |
| **第二次换位置** | **禁止再用「扩大覆盖」修法**，必须写出能对任意新对象回答「它该不该被守护」的**判别式** |
| **第三次** | 视为设计债，单开任务偿还 |

### 3. 单向断言从两侧夹住被约束量

`x <= B` / `x >= B` 只在越界时说话，**「量永远远离界」与「量被机制拦在界处」在它看来一样**，前者是空转。

- `x <= B` 另配 `x >= k·B`（`0<k<1`）；`x >= B` 另配 `x <= B/k`。给 `x >= B` 补 `x >= 0.5B` 是**恒真式**
- 让量走到 `k·B` 的**构造参数必须由 `B` 推出**，不得写死；否则界一变，测试红在错的地方、报错还指错方向
- **只对声称「某机制把量拦在界内」的断言强制**（clamp / 饱和 / 限速 / 配额）。纯不变量该有大余量 ⇒ 别逼它逼近界，另写对抗构造去顶界
- 报告给**比值**，不只写「通过」——只写通过时，空转与真守护打出的字一样

判据：**把被约束量改成永远不接近界的值，这条断言会不会红？** ⚠️ 它与「坏实现会不会红」是两问：后者预设实现有错，而空转常发生在实现正确时。

### 4. 其余五条

- **打印处理单元数**，0 个不得成功
- **每条接受路径都要有会失败的无效输入**；做不到的那条不构成检查
- **校验最终状态**，不把「运行过命令」当成「状态已成立」——创建/写入后回读再计数
- **被跳过的对象要能列出来**，不能只报数量
- **判别式自身的输入写错时必须显式失败**，不得静默跳过——否则守护集合可以静默变空而全部测试仍绿

## 何时用

**触发**：新增或修改校验脚本、投影器、格式门禁、CI 步骤；写任务文件里的验收命令；给现有门禁「再加一条检查」。

**不触发**：读别人的检查结果（那是 `task-acceptance-replay`）；审查业务代码（`semantic-code-review`）。

## 要防的诱人错误

九条全部真实发生过，其中四条是本框架自己的门禁被外部 review 抓出来的。

| 诱人错误 | 它为什么看起来对 |
|---|---|
| **默认档是最弱的那档** | 参数默认值写成了只读模式，门禁跑了、绿了、什么也没做 |
| **命令失败但脚本继续** | 建链接的命令失败只往 stderr 打了一行，计数照加、报「全部就位」、退出 0 |
| **字符串搜索当配置校验** | 配置整条被注释掉，`grep` 照样命中，报「已配置」 |
| **只查目标存在，不查关系** | 取代目标文件在 ⇒ 判通过；自指、成环、日期与文件名不符全部漏过 |
| **只报数量，不报成员** | 「跳过 44 个」看着很正常，实际里面藏着三条本该可解析的引用 |
| **校验作用于错误的对象** | 脚本的正则只匹配列表格式，被校验文件是表格 ⇒ 提取 0 条，却报满分 |
| **退出码取自管道末端** | `cmd \| tail; echo $?` 取到的是 `tail` 的，永远是 0 |
| **上界断言在正常构造下从未被逼近** | 断言通过了，测试名字也叫 `..._clamp`，看不出钳位从没触发过 |
| **判别式的标注写错路径被静默丢弃** | 加载不报错，其余标注照常生效，总数非 0 ⇒ 全绿 |

## 判断程序

### 1. 先定义作用集合，再写规则

一个门禁 = **一条规则 + 它作用的对象集合**。审查通常只看规则对不对，**集合才是最容易悄悄缩小的地方**。

写规则之前先列出：**该被守护的全部对象是什么？** 然后逐个问「它在这个集合里吗」。

特别点名两类最容易漏的：

- **推导 / 计算得出的值**——它们不在数据文件里，最容易被「自动生成的集合」绕开，而它们恰恰最该守
- **集合从「手工列举」改成「自动生成」之后**——边界变得不可见，看起来更可靠、实际更危险，必须显式列出成员并抽查

### 2. 收敛判据

> **新增一个此前没有的同类对象时，它是自动落入守护范围，还是需要有人记得去加？**
>
> **需要人记得 ⇒ 边界没定义好。**

答不出「自动」，这条门禁就还没写完，无论它当下能抓住多少东西。

### 3. 同类缺口第二次换位置：换修法，别再扩大覆盖

| 第几次 | 处置 |
|---|---|
| 第一次 | 正常修 |
| **第二次** | **禁止再用「扩大覆盖」修法**。必须写出一句**判别式**——能对任意新对象回答「它该不该被守护」，而不是再列举一类 |
| **第三次** | 视为**设计债**，单开任务偿还，不在原任务里顺手再补一格 |

反面实例：清单写不全 → 改成自动生成 → 生成器输入不全 → 改成三层来源 → 三层全是同一侧。**三次都真修掉了当次缺陷，但没有一次回答「边界该画在哪」**，于是下一类对象天然落在界外，且没有任何机制会告诉你。

判别式长什么样：*凡是由权威数据推导得出、且会进入结论的量，一律必须可从某个已解析的数据源取到。* ——它对任意新值都能回答，而「再加一类来源」不能。

**写完判别式之后还有一问：它的正向证据覆盖了它的全部载体吗？**

判别式常同时管几个载体（几种配置源、几条分支、几侧数据）。收敛演示只需要一个例子就能通，于是例子天然全落在同一侧，另一侧只剩「断言它不出现」这种负向断言 ⇒ **正向路径零覆盖**。判别式两侧都真通，**但证据只在一侧**——要自己往没验过的那侧补一个探针才知道。

### 4. 打印处理单元数，0 个不得成功

每次校验必须报告它**实际处理了多少个单元**。0 个，或数量与预期不符 ⇒ **该次校验无效**，不是通过。

「我用脚本核过了」不等于「脚本核的是这个对象」。

### 5. 集合必须可抽查

被跳过、被过滤、被认为不适用的对象，**要能被列出来**（一个 `--verbose` 就够），不能只报个数量。

理由见第 1 条：集合缩小是最不可见的失效方式，而列出来是唯一能发现它的动作。

### 6. 每条接受路径都要有会失败的无效输入

对每一条「满足条件即通过」的分支，构造一个**应当被拒绝**的输入，确认它真的变红。

做不到的那条分支，说明它不构成检查。

### 7. 单向断言要配「对侧接近约束」，且必须与界同源

`assert x <= B` / `assert x >= B` 形式的断言**只在越界时说话**。于是「x 永远远离 B」与「x 被机制拦在 B 处」在它看来完全一样，而前者是**空转**。

判据：

> **把被约束量改成一个永远不接近界的值，这条断言会不会红？**
>
> **不会 ⇒ 它没有在守护它声称的性质。**

#### 7a. 配套断言必须来自**对侧**

| 原断言 | 空转形态 | 配套断言（**从另一侧夹住**） |
|---|---|---|
| `x <= B`（安全上界） | 量永远远**小于** B | `x >= k·B`（`0<k<1`） |
| `x >= B`（安全下界） | 量永远远**大于** B | `x <= B/k`（或 `x <= B·(1+ε)`） |

「补一条下界」是错的说法：对 `x >= B` 写 `x >= k·B` 被原断言蕴含，是**恒真式**，零信息量。通用形式是**把量从界的另一侧夹住，钉在 B 附近的一条带里**。

#### 7b. 强制范围：只对「声称机制在起作用」的断言

- **声称某机制把量拦在界内**（clamp / 饱和 / 限速 / 背压 / 配额）⇒ **强制**配对侧约束。机制没被触发过，测试就没测到它。
- **纯不变量**，大余量才是期望结果（下标不越界、缓冲不溢出）⇒ **禁止**要求它逼近界。正确做法是**另写一个对抗性构造**去真正顶到界。

判法：看测试名与注释声称了什么。名字里有 `clamp` / `saturat` / `limit` / `throttle` 的属前者。

#### 7c. 对侧约束的参数必须由界推出，不得各自写死

若界是 `B`，让量走到 `≈k·B` 的**构造参数也必须从 `B` 算出来**（`param = k·B/rate`），不能一边阈值挂在 `B` 上、一边构造参数写死。

两条推论：

- 不同源 ⇒ **把空转的断言换成了脆弱的断言**。界一变，测试红在错的地方。
- **门禁的报错必须指向真因。** 一条会误导归因的红比不红更贵——它把人送去改错的地方。

⚠️ 界本身常是**假设值**（问询未闭合、待签核）。把测试钉在假设值上而不与它联动，等于让假设一变更就假失败。

#### 7d. 同族失效：一条断言写两遍不等于验了两件事

判法：把断言里的量**代换消元**，看剩几个**独立**约束。7a 那个恒真式是这个病的极端形态——消元后剩 0 个新约束。

#### 7e. 报告要给比值

不要只写「通过」，写出**量与界的比值**。它是这条规则唯一可被抽查的产物；只写「通过」时，空转和真守护打出来的字一模一样。

⚠️ **这一整类不在「把实现换成明显错误的版本会不会红」的射程内**——那一问预设实现有错，而空转常发生在**实现正确**时（忠于规格，而测试构造从未把量推进断言起作用的区域）。两问都要问。

### 8. 判别式自身的输入必须显式校验

防漂移机制（判别式、扫描集、标注表）**自己也有输入**。输入写错时它必须 raise，不得静默跳过：一条标注指向不存在的对象时若只是取不到值就 `continue`，**整条标注静默消失**，该对象悄悄不再被守护，而全部测试仍绿。

判据：

> **防漂移机制自身的输入写错时，它是显式失败，还是静默什么也不做？**
>
> **静默 ⇒ 守护集合随时可能在无人知晓的情况下变空。**

⚠️ 与第 4 条（处理单元数 0 不得成功）**不重复**：17 条标注里错 1 条时，单元数是 16，非 0，照样绿。总量检查抓不到逐条静默丢弃。

### 9. 校验最终状态，不把「运行过命令」当成「状态已成立」

创建、修改、写入之后**回读实际状态**再计数。命令没报错不等于状态成立——权限、冲突、竞态都会让它悄悄不生效。

### 10. 失败进统一计数，参数用闭集

- 所有失败走同一个错误计数并影响退出码；只往 stderr 打一行 = 没人会发现
- 参数是闭集：默认 / 只读 / 写入各自明确，**未知参数直接失败**，不要静默落进任何一档
- **默认档不能是最弱的那档**——默认是被跑得最多的那个

### 11. 在隔离环境跑负测试

本机的正确配置会掩盖缺陷：目标目录恰好不存在、配置恰好是对的、文件恰好没冲突。

负测试要在**隔离环境**里跑——临时 HOME、仓库临时副本——并显式制造冲突态（普通文件占位、链接指向别处、配置被注释、目录为空）。

## 停止条件

- 说不出这条门禁的作用集合 → 先定义集合，别先写规则
- 某条分支写不出会让它变红的输入 → 那条不是检查，删掉或重写
- 某条上/下界断言给不出「正常构造下被约束量逼近界」的数字 → **它在空转**，重写构造，不要只改断言措辞
- 打算给 `x >= B` 补一条 `x >= k·B` → **停**，那是恒真式；配套约束必须来自对侧
- 对侧约束的阈值与构造参数没有同一个来源（界变了它不跟着变）→ **停**，否则只是把空转换成脆弱
- 刚写完一个判别式，但只能给出单侧载体的正向证据 → 先补另一侧探针再说它成立
- 这是同一类缺口第三次换位置 → **停手**，单开任务偿还设计债

## 报告格式

| 检查项 | 作用集合 | 处理单元数 | 被约束量 / 界 | 负测试（输入 → 期望变红） | 隔离环境 |
|---|---|---|---|---|---|

「被约束量 / 界」一栏只对上下界断言填；差整数个数量级即为空转，填「空转」而不是「通过」。
