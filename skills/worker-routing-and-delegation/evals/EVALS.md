# worker-routing-and-delegation · eval

## 正触发

| 场景 | 期望 |
|---|---|
| 决定一个任务发给谁 | 触发；先问可验证性 |
| 决定要不要引入独立审查 | 触发；按「有无无法自我验证的部分」判 |
| 创建委托型子任务 | 触发；固定继承策略与回传约定 |

## 负触发

| 场景 | 为什么不该触发 |
|---|---|
| 任务已在飞 | 路由已定 |
| 换个仓下发同类任务 | 判据不变 |

## 诱人错误

| 场景 | 省力但错误的判断 | 本 skill 应给出的判断 | 判据 |
|---|---|---|---|
| 改动只有 3 行 | 小改动，自己顺手做 | 行数不是内部依赖、语义风险或可验证性的代理——三行改一个不变量比三百行加测试危险 | 判据：§1. 先问可验证性 |
| 本次是纯文档任务 | 跳过独立审查 | 文档同样含无法自我验证的事实主张；触发条件是「有没有我验证不了的部分」，不是文件类型 | 判据：§3. 独立审查的触发条件 |
| 任务属于 eval / 易造假域 | 不能发执行端 | 实测不成立；判据是**验收能不能机械核对** | 判据：§实测修正 |
| 委托时说「有需要就读上下文」 | 委托方会自己找 | 隐式继承。委托方看不到你的对话，只快照明确可继承的策略 | 判据：§4. 委托时固定四件事 |
| 子任务回传「我认为已完成」 | 可结算 | 结算由持有父子关系的一方发起，委托方不自行宣布通过 | 判据：§4. 委托时固定四件事 |
