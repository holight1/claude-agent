# Worker 路由与委托

**状态**：enabled
**消费者**：架构师
**投影**：无
**来源**：dsh 的委托边界 + DSH-003a（策略继承 / 管理者所有权 / 失败事实）+ 本框架实测修正
**核心判断**：这件事的结果，架构师能不能独立机械核对？

**本 skill 是判据，不是完整清单。** 判据的由来在下方「判据来源」的记录里。

## 判据来源

- `decisions/2026-08-21-worker-routing-single-criterion.md` — 单一判据（能否机械验证）与被删掉的旧判据
- `decisions/2026-08-21-skill-consumer-split-and-generated-projection.md` — 为什么它是架构师专用
- `evals/EVALS.md` — 每条判据对应的具体场景

## 何时用

**触发**：决定一个任务发给谁；决定要不要引入独立审查；创建委托型子任务。

**不触发**：任务已经在飞；只是换个仓下发同类任务。

## 要防的诱人错误

| 诱人错误 | 为什么错 |
|---|---|
| **按改动行数路由**（「超过 3 行就下发」） | 行数不是内部依赖、语义风险或可验证性的代理。三行改一个不变量，比三百行加测试危险得多 |
| **按话题域路由**（「eval 相关容易造假，不能发 DS」） | 实测不成立。真正的判据是**验收能不能机械核对** |
| **按文件类型决定要不要独立审查**（「纯文档任务跳过 Codex」） | 文档里同样有无法自我验证的事实主张。触发条件应是「架构师存在无法自我验证的部分」 |
| 让委托方"自己看着办，有需要就读上下文" | 隐式继承。委托方读到的和你以为它读到的不是一回事 |
| 失败时回传一大段推理 | 需要的是**有界且可归属**的事实：哪一步、什么对象、什么现象 |

## 实测修正（2026-08-20，practice-agent）

本地 DS 在两个任务上的表现**与「会 gate-game」的先验不符**：

1. 门槛写松时，它**精确满足字面，不多不少**——不补你的漏洞，但也不造假
2. 遇到**自相矛盾**的任务原文时，它按声明的**目的**而非字面执行，并在知识库里写明偏离理由

所以 worker 选择的判据是**「验收能不能机械核对」**，不是「话题是否属于易造假域」。

## 判断程序

### 1. 先问可验证性

> 这个任务返回后，我能不能用命令独立核对它做没做到？

- **能** → 可以发执行端。门槛写死，验收按 `task-acceptance-replay` 复跑
- **不能** → 三选一：改任务设计让它可验证（回 `task-contract-design`）／换 subagent（保有架构师上下文、能独立跑通并自审）／自己做

### 2. 再问语义细腻度与仓库内部依赖

需要理解框架内部约定、跨文件不变量、或"改这里会牵动那里"的活 → subagent，不发执行端。执行端在这类活上缺少判断所需的上下文，而任务文件补不全。

### 3. 独立审查的触发条件

**不是**按文件类型，而是：

> 这次交付里，有没有**架构师自己无法验证**的部分？

有 → 引入独立审查（Codex），并在请求里点名那部分。没有 → 不引入。

架构师应在每轮明确说出「本轮我无法自我验证的是 X」，由用户判断是否需要额外交叉审查——**这个判断不由架构师独占**。

### 4. 委托时固定四件事

| 项 | 要求 |
|---|---|
| 继承的上下文 | **只快照明确可继承的策略**；禁止隐式继承。委托方看不到你的对话 |
| 目标与停止条件 | 做到什么算完；什么情况下必须停下来报告而不是自行决定 |
| 回传约定 | 成功回传什么证据；失败回传**有界且可归属的事实**，不是推理过程 |
| 结算方 | 由**持有父子关系的一方**发起结算——委托方不自行宣布任务通过 |

### 5. 写入边界

委托前确认目标仓的写入策略（自有 / 上游 clone / 只读镜像），并在任务里点名。跨仓会话最容易的错是把 A 仓的策略用在 B 仓。

## 停止条件

- 判据落在「我说不清能不能验证」→ 先回 `task-contract-design`，不要先选 worker
- 需要委托方"理解我的意图"才能做对 → 意图没写进任务文件，不要下发
