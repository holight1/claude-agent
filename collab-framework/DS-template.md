## 编码规范（必须遵守）

### 硬性约束

- **单行**：≤ 80 字符
- **单函数**：≤ 100 行
- **单文件**：≤ 800 行
- **缩进**：4 个空格（不用 Tab）
- **风格**：K&R 风格（左花括号不换行）

### 文件头规则

**新建文件**：必须添加完整文件头：

```c
/*
 * @file [文件名]
 * @author [AUTHOR]
 * @date [YYYY/MM/DD]
 * @brief [准确描述该文件的职责，一句话]
 *
 * Copyright (C) [YEAR] [COMPANY]
 * All rights reserved.
 *
 * This file is a part of [PROJECT_SCOPE].
 */
```

**修改已有文件**：
- `@author`：若做了实质性修改，在现有作者后追加 `[AUTHOR]`；小改动不加
- `@brief`：若文件职责有变化则更新，否则不动
- `Copyright`：不得修改；若当前年份不在年份列表中，追加即可

## 工作流程

1. 读取 `DS.md`（本文件）
2. 若 `CLAUDE.md` 存在，读取（构建/测试命令 + 项目专属规则）；若不存在，跳过
3. 按任务相关性读取 `code-agent/knowledge/` 下的主题文件（README.md 有索引）
4. 读取任务文件 `code-agent/tasks/xxx.md`
5. 参考知识库中的相关内容，避免重复调研
6. 按任务要求执行
7. 在任务文件末尾的「完成区」按规范格式填写结果（见下）
8. **将任务文件顶部的 `**状态**` 字段更新为 `已完成`**（必须执行，不得遗漏）
9. **检查是否需要更新知识库**（见下方「知识库更新规则」）
10. 如需更新，修改 `code-agent/knowledge/` 下对应主题文件，并在 `10-changelog.md` 添加一行记录

## 完成区填写规范

每次任务完成，**完成区必须包含以下字段**（缺项填"无"）：

```markdown
## 完成区

**Commit**：`<hash>` 或 `无`
**测试结果**：通过 N/M；失败原因：...
**新发现/坑**：...
**知识库更新**：§XX.Y 已更新 / 无
```

## 长任务阻塞规则（"不做完不要返回"任务）

若任务文件注明 **"不做完不要返回"** 或 **"有问题记录到 ~/NNNa-progress.md"**：

- 单步阻塞时，记录到 `~/NNNa-progress.md`，格式：
  ```
  ## [HH:MM] 阶段X 遇到问题
  **现象**：...  **已尝试**：...  **当前状态**：阻塞/绕过
  ```
- 继续推进其余 phase，不得提前退出
- 全部 phase 完成或均阻塞，才返回

## 遇到问题时的查询顺序（必须遵守）

1. **先查知识库** `code-agent/knowledge/`（`README.md` 有主题索引）
   - 若知识库有答案，直接采用，**不得另行搜索代码来"验证"**

2. **知识库未覆盖时，再查源码**
   - 只读取与问题直接相关的文件
   - 搜索结论有价值时，任务完成后更新到知识库

3. **禁止行为**：
   - 不得跳过知识库直接搜索代码
   - 不得对知识库已有结论重复调研
   - 不得用 `grep -r` / `find` 全库扫描替代查阅知识库

## 知识库更新规则（每次任务完成后必须执行）

满足以下任一条件时，更新 `code-agent/knowledge/` 下对应主题文件：

1. 新增文件/模块 → `01-project-structure.md`
2. 实现新功能/接口 → 相关主题文件或新建主题文件
3. 发现关键技术细节/陷阱 → 对应主题文件
4. 完成调研任务 → 相关主题文件
5. 修复重要问题 → 相关主题文件

同时在 `10-changelog.md` 添加一行日期记录。

知识库引用格式：**`§文件号.小节号`**（如 `§25.3`），不要写行号。
