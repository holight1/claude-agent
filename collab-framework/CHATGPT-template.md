## 编码规范（必须遵守）

### 硬性约束

- **单行**：≤ 80 字符
- **单函数**：≤ 100 行
- **单文件**：≤ 800 行
- **缩进**：4 个空格（不用 Tab）
- **风格**：K&R 风格（左花括号不换行）

### 文件头规则

**新建文件**：必须添加完整文件头：

```c
/*
 * @file [文件名]
 * @author [AUTHOR]
 * @date [YYYY/MM/DD]
 * @brief [准确描述该文件的职责，一句话]
 *
 * Copyright (C) [YEAR] [COMPANY]
 * All rights reserved.
 *
 * This file is a part of [PROJECT_SCOPE].
 */
```

**修改已有文件**：
- `@author`：若做了实质性修改，在现有作者后追加 `[AUTHOR]`；小改动不加
- `@brief`：若文件职责有变化则更新，否则不动
- `Copyright`：不得修改；若当前年份不在年份列表中，追加即可

## 工作流程

1. 读取 `CHATGPT.md`（本文件）
2. 按任务相关性读取 `code-agent/knowledge/` 下的主题文件（README.md 有索引）
3. 读取 `CLAUDE.md`（构建和测试详情）
4. 读取任务文件 `code-agent/tasks/xxx.md`
5. 参考知识库中的相关内容，避免重复调研
6. 按任务要求执行
7. 在任务文件的「执行结果」部分填写结果
8. **检查是否需要更新知识库**（见下方「知识库更新规则」）
9. 如需更新，修改 `code-agent/knowledge/` 下对应主题文件，并在 `10-changelog.md` 添加一行记录

## 知识库更新规则（每次任务完成后必须执行）

满足以下任一条件时，更新 `code-agent/knowledge/` 下对应主题文件：

1. 新增文件/模块 → `01-project-structure.md`
2. 实现新功能/接口 → 相关主题文件或新建主题文件
3. 发现关键技术细节/陷阱 → 对应主题文件
