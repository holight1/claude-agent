# AI 协作框架

## 协作流程

```
用户需求 → Claude 创建任务 → DS 执行 → Claude Review → 小问题自修/大问题返工 → 自动提交
```

## 任务文件规范

### 命名与位置

`code-agent/tasks/<编号>-<类型>-<简述>.md`

- 编号：三位数字 + 字母后缀，如 `035a`、`035b`
- 类型：`research`、`implement`、`fix`、`continue`、`review`

### 状态值

`待执行` / `执行中` / `已完成` / `已作废`

---

```markdown

| 设计参考 | 路径 | 章节 |
|---------|------|------|
| <设计文档名> | `code-agent/designs/<file>.md` | 全文 |

## 变更文件清单

```
<file1>  (+N -M)

```

## Review 要求

1. [需要逐项确认的结构体/宏/常量]
2. [需要逐项确认的核心函数/流程]
3. 测试用例覆盖（对照验收条件）
4. 代码风格（文件头、命名、缩进）

```

## 知识库

- 位置：`code-agent/knowledge/`，`README.md` 有主题索引
- 设计文档：`code-agent/designs/`
- 更新规则：完成任务后若有新发现，更新对应主题文件并在 `10-changelog.md` 追加一行记录

## Review 与提交规则

- DS/Gemini 不做 commit；Claude/Codex review 通过后负责本地 commit
- review 中发现的轻量问题由 Claude/Codex 直接修复并验证，包括测试断言、文档口径、漏改引用、格式/命名、局部边界条件等
- 涉及设计不符、路线不通、较大重构、跨模块接口/ABI 影响的问题，不直接修；需要向用户说明，并按需创建 `*-review-fixes.md`
- review 无阻断问题、轻量问题已修复且验收通过后，自动本地 commit，无需再次等待用户确认
- 不自动 push；push 必须等待用户明确确认

### Review 分类（审查侧重不同）

| 情况 | Claude review 重点 |
|------|-------------------|
| 通过已有测试 | pass/fail 结果 + 变更范围与任务描述是否一致 |
| 新增测试 | ① 场景覆盖完备性 ② CHECK 语义正确性 ③ CHECK-NOT 范围盲区 |

新增测试的具体 CHECK 模式由 DS 跑实际工具输出后写，Claude 不预先指定。
Claude review 时判断：场景有无遗漏、CHECK 是否测了正确的语义（语义边界如 NaN、溢出等）。
