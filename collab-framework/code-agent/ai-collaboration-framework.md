# AI 协作框架

## 协作流程

```
用户需求 → Claude 创建任务 → DS 执行 → Claude Review → 小问题自修/大问题返工 → 自动提交
```

## 任务文件规范

### 命名与位置

`code-agent/tasks/<编号>-<类型>-<简述>.md`

- 编号：三位数字 + 字母后缀，如 `035a`、`035b`
- 类型：`research`、`implement`、`fix`、`continue`、`review`

### 状态值

`待执行` / `执行中` / `已完成` / `已作废`

---

### 标准任务模板

```markdown
# <任务标题>

**状态**：待执行
**执行环境**：本地 DS · <仓库名>

## 背景

[一段话说明上下文]

## 前置知识

**此 section 必填，不可省略。**

- `code-agent/knowledge/<文件>.md` — §X.X   ← Claude 已知章节时直接填
- 关键词：`<keyword1>`、`<keyword2>`         ← Claude 不确定时填关键词，DS 自行在 knowledge/ 中搜索定位
- 任务 <编号> 完成区（已确认的结论）

DS 执行前须先读完前置知识中列出的所有章节，或搜索定位后再阅读，确认背景后再开始任务。

## 任务内容

[详细描述]

## 验收

```bash
[验收命令]
```

## 完成区

<!-- DS 在此填写结果 -->
```

### Review 任务模板

```markdown
# <编号> — Review: <功能名称>

**状态**：待执行
**执行环境**：本地 DS · <仓库名>

## 背景

提交 `<commit-hash>` 基于以下设计实现了 <功能>：

| 设计参考 | 路径 | 章节 |
|---------|------|------|
| <设计文档名> | `code-agent/designs/<file>.md` | 全文 |

## 变更文件清单

```
<file1>  (+N -M)
<file2>  (+N)
```

## Review 要求

1. [需要逐项确认的结构体/宏/常量]
2. [需要逐项确认的核心函数/流程]
3. 测试用例覆盖（对照验收条件）
4. 代码风格（文件头、命名、缩进）

## 输出格式

在本任务末尾追加：

```markdown
## Review 结论

### 符合设计的部分
- ...

### 偏差与问题
| 文件 | 行号 | 问题描述 | 严重程度（阻断/警告/建议） |
|------|------|---------|--------------------------|

### 总体评价
通过 / 需修改（说明理由）
```
```

## 知识库

- 位置：`code-agent/knowledge/`，`README.md` 有主题索引
- 设计文档：`code-agent/designs/`
- 更新规则：完成任务后若有新发现，更新对应主题文件并在 `10-changelog.md` 追加一行记录

## Review 与提交规则

- DS/Gemini 不做 commit；Claude/Codex review 通过后负责本地 commit
- review 中发现的轻量问题由 Claude/Codex 直接修复并验证，包括测试断言、文档口径、漏改引用、格式/命名、局部边界条件等
- 涉及设计不符、路线不通、较大重构、跨模块接口/ABI 影响的问题，不直接修；需要向用户说明，并按需创建 `*-review-fixes.md`
- review 无阻断问题、轻量问题已修复且验收通过后，自动本地 commit，无需再次等待用户确认
- 不自动 push；push 必须等待用户明确确认
