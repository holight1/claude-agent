# AI 协作框架

## 协作流程

```
用户需求 → Claude 创建任务 → GPT 执行 → Claude Review → 完成/返工
```

## 任务文件规范

### 命名与位置

`code-agent/tasks/<编号>-<类型>-<简述>.md`

- 编号：三位数字 + 字母后缀，如 `035a`、`035b`
- 类型：`research`、`implement`、`fix`、`continue`、`review`

### 状态值

`待执行` / `执行中` / `已完成` / `已作废`

---

### 标准任务模板

```markdown
# <任务标题>

**状态**：待执行
**执行环境**：本地 GPT · <仓库名>

## 背景

[一段话说明上下文]

## 前置知识

- `code-agent/knowledge/<文件>.md` — §X.X
- 任务 <编号> 完成区（已确认的结论）

## 任务内容

[详细描述]

## 验收

```bash
[验收命令]
```

## 完成区

<!-- GPT 在此填写结果 -->
```

---

### 进度表任务模板（多步骤任务）

在"任务内容"后加进度表和分步说明：

```markdown
## 进度表

| # | 步骤 | 状态 |
|---|------|------|
| 1 | 步骤一 | 待执行 |
| 2 | 步骤二 | 待执行 |

---

### 步骤 1：[标题]

[详细说明]

**验收**：`<命令>`

完成后更新进度表状态为 `done`，继续下一步。

---

### 步骤 2：[标题]
...
```

---

### Review 任务模板

```markdown
# <编号> — Review: <功能名称>

**状态**：待执行
**执行环境**：本地 GPT · <仓库名>

## 背景

提交 `<commit-hash>` 基于以下设计实现了 <功能>：

| 设计参考 | 路径 | 章节 |
|---------|------|------|
| <设计文档名> | `code-agent/designs/<file>.md` | 全文 |

## 变更文件清单

```
<file1>  (+N -M)
<file2>  (+N)
```

## Review 要求

1. [需要逐项确认的结构体/宏/常量]
2. [需要逐项确认的核心函数/流程]
3. 测试用例覆盖（对照验收条件）
4. 代码风格（文件头、命名、缩进）

## 输出格式

在本任务末尾追加：

```markdown
## Review 结论

### 符合设计的部分
- ...

### 偏差与问题
| 文件 | 行号 | 问题描述 | 严重程度（阻断/警告/建议） |
|------|------|---------|--------------------------|

### 总体评价
通过 / 需修改（说明理由）
```
```

## 知识库

- 位置：`code-agent/knowledge/`，`README.md` 有主题索引
- 设计文档：`code-agent/designs/`
- 更新规则：完成任务后若有新发现，更新对应主题文件并在 `10-changelog.md` 追加一行记录
