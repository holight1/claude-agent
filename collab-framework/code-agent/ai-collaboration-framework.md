# AI 协作框架：Claude（设计）+ ChatGPT Codex（编码）

## 协作流程概览

```
用户需求 → Claude 设计 → 设计文档 → ChatGPT Codex 编码 → 代码提交 → Claude Review → 完成/返工
```

## 阶段一：设计（Claude）

### 输入
- 用户需求描述
- 相关代码上下文（如有）

### 输出：设计文档

设计文档使用以下固定格式，保存在 `code-agent/designs/` 目录下：

```markdown
# 设计文档：[功能名称]

## 1. 需求概述
简要描述要实现什么功能，解决什么问题。

## 2. 设计决策
关键的技术选型和架构决策，以及原因。

## 3. 文件变更清单
| 文件路径 | 操作 | 说明 |
|---------|------|------|
| path/to/file.c | 新建 | ... |
| path/to/file.h | 修改 | 添加函数声明 |

## 4. 接口定义
// 完整的函数签名、结构体定义、枚举等
// 包含详细注释说明参数和返回值

## 5. 实现步骤
按顺序列出具体实现步骤，每步应该是原子性的、可验证的。

1. 步骤一：...
2. 步骤二：...

## 6. 测试要求
- 需要编写的测试用例
- 测试文件位置
- 预期测试覆盖

## 7. 约束与注意事项
- 代码风格要求
- 需要避免的陷阱
- 与现有代码的兼容性要求
```

## 阶段二：编码（ChatGPT Codex）

### 输入
- 设计文档
- CLAUDE.md（项目构建和测试说明）
- 相关源文件（设计文档中引用的）

### 编码规范

1. **严格遵循设计文档**
   - 按照「文件变更清单」操作文件
   - 按照「接口定义」实现接口
   - 按照「实现步骤」顺序编码

2. **代码风格（参照现有代码）**
   - 遵循项目既有的代码风格
   - 保持命名一致性
   - 缩进使用 4 个空格（不用 Tab）

3. **代码长度限制（硬性约束）**
   - **单行**：不超过 80 字符
   - **单个函数**：不超过 100 行（含空行和注释）
   - **单个文件**：不超过 800 行
   - 若逻辑复杂需超限，必须拆分为多个函数或文件

4. **文件头（Copyright 与作者）**

   - 规则详见 `CHATGPT.md`「文件头规则」节
   - 新文件：必须有完整文件头，Copyright 用 `Sunmmio Inc.`，开头 `/*`（单星号）
   - 已有文件：Copyright 不得修改（最多追加当前年份）；实质性修改时追加作者

5. **代码组织**
   - 长表达式拆分为多行，每行一个参数或操作
   - 复杂条件判断提取为有意义的布尔变量
   - 相关功能分组，组间用空行分隔
   - 避免深层嵌套（最多 3 层）

6. **禁止事项**
   - 不得修改设计文档未列出的文件
   - 不得改变已有函数的签名（除非设计文档明确要求）
   - 不得引入新的外部依赖
   - 不得跳过或简化设计文档中的步骤

7. **必须事项**
   - 每个函数必须有错误处理
   - 所有资源分配必须有对应的释放路径
   - 编写设计文档要求的测试用例
   - 确保代码能通过编译

### 输出

**代码文件**
- 修改后的代码文件
- 新建的测试文件

**完成文档**（必须提供）

根据任务类型选择对应格式：

**BUG 修复文档**：
```markdown
## BUG 修复报告

### 问题现象
[描述 BUG 的表现]

### 根因分析
[分析 BUG 产生的原因，定位到具体代码]

### 修复方案
[说明如何修复，为什么这样修复]

### 影响范围
[修复可能影响的其他功能]

### 验证方法
[如何验证 BUG 已修复]
```

**功能实现文档**：
```markdown
## 功能实现报告

### 功能概述
[一句话描述实现了什么]

### 实现逻辑
[描述核心逻辑流程，可用伪代码或流程图]

### 关键设计点
[说明重要的设计决策]

### 与设计的偏差
[如有偏差，说明原因]

### 验证方法
[编译和测试命令]
```

## 阶段三：Review（Claude）

### Review 检查清单

1. **符合性检查**
   - [ ] 是否按设计文档实现
   - [ ] 接口是否与设计一致
   - [ ] 是否有未授权的文件修改

2. **正确性检查**
   - [ ] 逻辑是否正确
   - [ ] 边界条件是否处理
   - [ ] 错误处理是否完整
   - [ ] 资源是否正确释放

3. **代码质量**
   - [ ] 是否符合代码风格
   - [ ] 命名是否清晰
   - [ ] 注释是否清晰有意义
   - [ ] 复杂逻辑是否有注释说明
   - [ ] 是否有不必要的复杂性

4. **安全性**
   - [ ] 是否有缓冲区溢出风险
   - [ ] 是否有内存泄漏
   - [ ] 是否有竞态条件

5. **测试**
   - [ ] 测试是否覆盖主要场景
   - [ ] 测试是否能通过

6. **完成文档**
   - [ ] 是否提供完成文档
   - [ ] BUG 修复：是否有根因分析和修复方案
   - [ ] 功能实现：是否有逻辑描述
   - [ ] 文档内容是否准确完整

### Review 结果

- **通过**：代码可以合并
- **小修改**：列出需要修改的点，修复后可直接合并
- **返工**：存在重大问题，需要重新编码

## 沟通协议

### 文件通信机制

Claude 和 ChatGPT Codex 通过仓库中的文件进行任务传递：

**任务目录**：`code-agent/tasks/`

**任务文件命名**：`[序号]-[类型]-[简述].md`
- 类型：`research`（调研）、`implement`（实现）、`fix`（修复）、`continue`（继续）
- 示例：`001-research-async-msg-analysis.md`
- 继续任务示例：`002-continue-research-xxx.md`（继续 002 任务）

**任务状态**：
- `pending` - 待执行
- `in_progress` - 执行中
- `completed` - 已完成，等待 review
- `approved` - 已通过
- `rejected` - 需返工

### 任务文件格式

#### 单次任务格式

```markdown
# 任务：[任务标题]

**状态**：pending
**分配给**：ChatGPT Codex
**创建者**：Claude

- [避免重复调研的已知内容]

基于知识库已有内容，本任务聚焦于**补充调研/实现**。

#### 进度表任务格式

适用于较大的任务，需要多次执行。每次只完成一个步骤，便于小 context 模型分步执行。

**特点**：
- 进度表清晰显示每步状态（`pending` / `done`）
- 每步有独立的验证命令
- 步骤之间有分隔符 `---`，便于定位当前任务

```markdown
# 任务：[任务标题]

**状态**：pending
**分配给**：ChatGPT Codex
**创建者**：Claude

## 前置知识

按任务相关性读取 `code-agent/knowledge/` 下的主题文件（README.md 有索引）：
- [主题文件名]（简要说明相关性）
- [主题文件名]

注：只读取与本任务相关的主题文件，避免阅读所有文件。

## 任务描述

[总体描述]

## 进度表

| 2 | 步骤二描述 | pending | |
| 3 | 步骤三描述 | pending | |

## 执行指南

按顺序逐个完成所有步骤，每完成一个后更新进度表状态为 `done`，然后**继续下一个**直到全部完成。

---

```

**验证**：
```bash
[验证命令]
```

全部步骤完成后：
```bash

### Claude → ChatGPT Codex（通过文件）

1. Claude 在 `code-agent/tasks/` 创建任务文件
2. 用户告知 ChatGPT Codex：**使用标准指令模板**（见下方）
3. ChatGPT Codex 读取任务文件，执行任务
4. ChatGPT Codex 将结果写入同一文件的「执行结果」部分

**标准指令模板**（每次下发任务必须使用）：

```
请先读取 CHATGPT.md，然后执行 code-agent/tasks/xxx.md
```

注：CHATGPT.md 中已包含知识库路径，ChatGPT 会自动阅读。

**全局配置文件**：`CHATGPT.md` 包含：
- 上下文隔离规则（放弃之前任务）
- 编码规范
- 工作流程
- 禁止事项

ChatGPT Codex 每次工作前必须读取此文件，确保遵守规则。

**知识库文件**：`code-agent/knowledge/` 目录，按主题分文件，README.md 有索引。

Claude 和 ChatGPT Codex 在执行调研或修复任务时按需读取相关主题文件，避免重复调研已知内容。

## 维护命令

### optimize-context

**用途**：清理已完成任务、同步知识库、减少 context 消耗

**触发方式**：用户说 "执行 optimize-context" 或 "优化 context"

**详细流程**：见 `code-agent/commands/optimize-context.md`

**执行内容**：
1. 列出所有任务状态，识别可清理任务
2. 检查待清理任务是否有内容需同步到知识库
3. 检查知识库是否有冗余信息
4. 归档已完成任务到 `code-agent/tasks/archived/`
5. 更新 session-context.md

**注意**：设计 MD（`code-agent/designs/`）由用户手动清理
