# GPT 调研任务生成器

自动生成格式规范的调研任务文件。

## 输入

调用时需提供：
- **问题描述**：需要调研什么
- **调研方向**：关注哪些方面
- **任务编号**（可选）：如 `036a`，不提供则自动编号
- **执行环境**（可选）：如 `本地 GPT · SuBase-SY`，不提供则询问用户

## 输出

在 `code-agent/tasks/` 生成完整的任务 markdown 文件。

## 生成流程

1. **确定编号**：扫描 `code-agent/tasks/` 现有文件，确定下一个编号
2. **确定相关知识**：根据调研方向，查找 `code-agent/knowledge/` 中相关主题文件，**标注章节号**（如 §4.3），不要要求行号
3. **评估插桩需求**：如果调研涉及运行时状态追踪、调用链分析、执行时序，建议启用插桩
4. **生成任务文件**：使用下方模板

## 任务文件模板

```markdown
# 任务：[调研标题]

**状态**：待执行
**执行环境**：[本地 GPT · <仓库名> / 远端 <nickname> GPT · <仓库名> / Gemini]

## 前置知识

- `code-agent/knowledge/<文件>.md` §<章节号> — [与本任务的相关性]

## 任务描述

[具体的调研问题和目标]

## 调研范围

### 需要分析的文件
- [文件路径1] — [分析什么]
- [文件路径2] — [分析什么]

### 需要回答的问题
1. [具体问题1]
2. [具体问题2]

## 输出要求

1. 回答上述所有问题，给出具体代码位置和行号
2. 若有新发现，更新 `code-agent/knowledge/<对应主题文件>.md` 对应章节

---

## 完成区

<!-- GPT 在此填写结果 -->
```

## 关键规则

- **知识库引用标章节号**（如 §4.3），不要要求行号（行号会变）
- **调研问题必须具体**，禁止模糊目标如"了解 XX 机制"
- **每个子问题可独立验证**，便于分步执行
- **复杂调研考虑拆分**：每个子任务聚焦单一问题，编号用字母后缀
- **评估插桩需求**：运行时分析场景建议启用，在任务头部标注 `**调试选项**：允许插桩`
