# 框架决策记录进框架仓

**状态**：现行
**日期**：2026-08-21
**触发**：sim 会话为解决 SIM-001a 的三条缺陷改了本仓的 skill 与脚本，理由全部写在 `~/sim/tasks/SIM-001a` §8–§9，本仓一条都没有。
**作用面**：新增 `decisions/`、`scripts/check-decisions.sh`；`README.md` 的权威归属表。

## 决定

建立 `decisions/`：改动本框架的决策，记录进本仓。项目侧的任务文件只留指针，不作为框架决策的权威源。

状态闭集 `现行 / 已取代 / 已否决 / 已归档`，必备小节 `## 决定 / ## 为什么 / ## 备选方案 / ## 验收证据`，取代检查在写入时做，归档冻结且免除演进中的门禁。制度全文见 `decisions/README.md`。

## 为什么

框架被多个架构师会话共用，各自坐在不同的项目根上。规则改了而理由留在某个项目里，其他会话**从框架仓查不到任何原因**——看得到规则，看不到规则为什么长这样。结果只有两种：盲从，或者独立地把它改回去。

`git log` 记录了改了什么，但回答不了「当时还有哪些选择，为什么没选」。那部分信息一旦丢失，重新获得的成本等于重走一遍踩坑过程。

## 备选方案

- **只靠 commit message**。放弃：message 是线性的、按改动切分的，而一条决策常跨多次提交；且没有状态——无法表达「这条已被取代」。
- **照抄 dsh 的 `.agents/notes/`**（proposed/implemented/rejected/archived 四目录 + 闭集 class + 三个门禁 + SHA-256 append-only manifest）。放弃：dsh 有 723 篇记录、43 个作者；本仓个位数记录、一个用户。目录树与 manifest 的收益来自规模，在这里只是负担。**保留的是它的语义**（目录/状态即权威等级、写入时取代检查、归档冻结免门禁），丢掉的是它的规模机械。
- **记在用户的 memory 里**。放弃：memory 是单个架构师的，不随仓库分发；换机器或换会话就没了，而框架恰恰是跨会话共享的那个东西。

## 验收证据

`scripts/check-decisions.sh` 校验状态闭集、四个必备小节、`## 备选方案` 非空、`已取代` 的目标可达；0 条记录时退出码 1。负测试见 `2026-08-21-project-to-framework-backflow.md` 的同批验证记录。
