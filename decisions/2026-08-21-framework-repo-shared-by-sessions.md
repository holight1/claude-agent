# 框架仓由多会话共写，不留未提交状态

**状态**：现行
**日期**：2026-08-21
**触发**：sim 会话改了本仓 5 处（`sync-skills.sh`、两个 `SKILL.md`、两个 `enabled/` 链接）并以未提交状态留在工作树里。`~/agent` 会话下一步若按习惯 `git add -A && git commit`，会把它们扫进自己的提交并署上自己的理由；若为求干净跑 `git checkout .`，直接销毁。
**作用面**：`scripts/check-framework.sh`（新增）、`USAGE.md §6`。

## 决定

**框架仓不留未提交状态。** 改完当轮 commit（不 push），commit message 首行标明来源工作区。

`scripts/check-framework.sh` 把「工作树非空」变成一条**会失败的校验**，作为跑任何框架改动前后的守卫。

代其他会话装箱时，commit message 必须写明：改动非本会话所作、原始理由在哪里、本会话做了什么级别的 review。

## 为什么

框架仓是**唯一被多个架构师会话同时写**的仓（`~/agent`、`~/sim`、`~/modules/base-sw` 各有会话），却是唯一没有交接约定的仓。项目仓有「执行端装箱 → 架构师复跑」的边界，框架仓在架构师之间没有任何等价物。

dsh 的答案是 PR + CI。本框架没有 PR，也没有 CI，所以只能退到最轻的机械化：**不留悬空状态**，让每一处改动都有作者和理由。

未提交状态的危害不对称：丢失是静默的、不可逆的，而多提交一次的代价只是一条 message。

## 备选方案

- **每个会话用自己的分支**。放弃：本框架不做 push，分支只存在本地；多会话在同一工作树上切分支会互相打断，风险高于收益。
- **给每个会话一份框架仓 clone**。放弃：`~/.claude/skills` 等客户端投影只能指一个路径，多份 clone 会让「哪份是生效的」变成新的漂移源。
- **约定只有一个会话有权改框架**。放弃：与实际相反——真正的改进恰恰来自在项目里踩到坑的那个会话，剥夺它的写权限等于让改进绕远路或者不发生。

## 验收证据

本决策的直接产物：sim 会话那 5 处改动已由 `~/agent` 会话装箱为 `f1f1f56`，message 写明「由 sim 工作区的架构师会话做出，非本会话作者」、原始理由位置、以及文档级 review 的三条待跟进。

`scripts/check-framework.sh` 的工作树守卫已用反例证伪：制造一处未提交改动 → 退出码 1。
