# decisions/ — 框架决策记录

**改框架的理由，记录在框架仓。**

本目录存放对 `~/claude-agent` 本身的改动决策：为什么这么改、当时的备选是什么、被什么取代。它不是变更日志——变更轨迹看 `git log`，本目录回答的是 **git log 回答不了的那部分：当时还有哪些选择，为什么没选。**

## 为什么需要它

框架被**多个架构师会话**共同使用（`~/agent`、`~/sim`、`~/modules/base-sw` …各有自己的会话）。一个会话在项目里踩到坑、改了框架，理由如果只留在那个项目的任务文件里，**其他会话从框架仓查不到任何原因**——它们会看到规则，看不到规则为什么长这样，于是要么盲从，要么独立地把它改回去。

这不是假想：`semantic-code-review` 的正文由 sim 会话补写，理由写在 `~/sim/tasks/SIM-001a-spec-ir-determinism.md` §8–§9，本仓在 2026-08-21 之前**一条都没有**。

## 格式

文件名 `YYYY-MM-DD-<kebab-topic>.md`。正文前四行固定：

```markdown
# <决策标题>

**状态**：现行
**日期**：2026-08-21
**触发**：<什么事件迫使做这个决定，一句话>
**作用面**：<改了哪些文件 / 哪些角色受影响>
```

必备小节：`## 决定` / `## 为什么` / `## 备选方案` / `## 验收证据`。

## 状态闭集

| 状态 | 含义 |
|---|---|
| `现行` | 当前有效 |
| `已取代` | 被另一条决策取代，**必须写明被谁取代** |
| `已否决` | 提出过并被否，正文记录理由 |
| `已归档` | 冻结在 `archive/`，不可编辑、不可作当前权威 |

## 四条纪律

**一 · 事实可就地改写，决策不可改写。**
决策记录里过时的**事实**（路径、命令、数量）就地改对，不追加「原先是 X」。但**决定本身不改写**——要改就写新记录并把旧的标 `已取代`。区别在于：读者需要知道现在算什么（事实），也需要知道当初为什么这么定（决策）。

**二 · 取代检查在写入时做。**
写一条新决策时，当场检查它是否推翻了已有的某条；推翻了就同时把旧的改成 `已取代` 并写明去向。不靠事后审计——事后审计永远排在别的事后面。

**三 · 备选方案是记录，不是编造。**
`## 备选方案` 写**当时真实考虑过并放弃的**选项和放弃的代价。没有真实备选就写「无备选：<为什么这件事没有第二种做法>」。**不要为了填满小节而发明选项**——编造的备选会让后来者以为某条路已经论证过了。

**四 · 只保留还在阻止诱人错误的记录。**
一条 `已否决` 的记录，只在「输掉的那个提案仍然是个诱人错误」时才留着——即：它有正当推理路径，下一个人会独立地重新提出来，而反驳它需要现场没有的信息。不满足就删掉，别攒。

## 归档

`archive/` 下永久冻结：不可编辑、不可改格式、不可移动删除，不可作当前权威。**归档内容免除本目录演进中的格式门禁**——用今天的格式去卡昨天冻结的文件，只会逼人改冻结件。

## 门禁

```bash
scripts/check-decisions.sh     # 校验状态闭集、必备小节、取代关系可达
scripts/check-framework.sh     # 上面这条 + skill 校验 + 工作树守卫
```
