# 审查角色文件按角色命名，不按厂商

**状态**：现行
**日期**：2026-08-21
**触发**：`~/sim` 的独立 reviewer 是执行端自起的 subagent（`~/sim/DS.md` §10「完成后必须自起独立 subagent 按 `CODEX.md` review」），**根本不是 Codex**；文件名在至少一个项目里已经是事实错误。同时审查节名已经分叉：模板写 `## Codex Review`，`~/sim` 三个任务文件都写 `## Subagent Review`。
**作用面**：`collab-framework/REVIEWER-template.md`（原名 CODEX-template.md，已 git mv）；`USAGE.md` §2.1 与 §5.x；`README.md`；`skills/` 与 `decisions/` 中的引用。

## 决定

- 模板 `CODEX-template.md` → **`REVIEWER-template.md`**，项目侧文件名 `CODEX.md` → **`REVIEWER.md`**
- 审查节名 `## Codex Review` / `## Subagent Review` → **`## 独立审查`**
- 模板正文的角色行去厂商化，并写明「角色不绑厂商：你可能是 Codex、执行端自起的 subagent、或另一个架构师会话」
- **`DS.md` 不改名**（理由见下）
- **过渡期规矩**：框架现在改名；既有项目由各自的会话在下次同步框架时改，连 `DS.md` 里的引用与任务文件节名一起改。**以该项目实际存在的文件名为准**，不要两个名字都写

## 为什么

**分叉已经发生，而节名分叉有机械代价。** `task-acceptance-replay` 要求架构师核对审查节，但有两个节名，**任何门禁都无法机械定位它**。节名之所以会分叉，正因为它绑了厂商——换个执行端那个名字就不成立。统一之后才可能加门禁：任务标已完成时必须存在 `## 独立审查` 节且结论在闭集内。

**框架自己的散文早就去厂商化了。** `README.md` 权威表写「独立 reviewer 的通用检查」，`semantic-code-review` 写「消费者：独立 reviewer」，`~/sim/CODEX.md` 开头写「你是 sim 工作区的独立 reviewer」。只有文件名和模板角色行还留着厂商名——它是残留物。

**没有工具耦合成本。** `CODEX.md` 是本框架发明的、**显式调用**的文件名（模板里写着「收到『请先读取 CODEX.md』时」），不是任何工具的自动发现约定。改名不会碰坏宿主行为。

**为什么 `DS.md` 不一起改**：判据是看**框架自己的散文用哪个词**。「DS」在散文里已经是角色名（「本地 DS · 仓库名」「DS 完成区」「DS-common.md」），已经词汇化，改名是纯成本；「Codex」在散文里一律说「独立 reviewer」，只有文件名留着。两者情况不同，不该一起动。

## 备选方案

- **只统一节名，不改文件名**。放弃：文件名是每个项目会话每天看见的东西，留着厂商名会让「不是 Codex 的 reviewer 适不适用这份文件」反复被问；而这个疑问正是节名当初分叉的起点。
- **改用 `AGENTS.md`**。放弃：那是 Codex 与 opencode 的**自动发现**文件名，改用它会让该文件在执行端做实现任务时也被自动加载——审查角色的约束会漏进实现角色。显式调用是这份文件的必要属性。
- **`DS.md` 一并改成 `EXECUTOR.md`**。放弃：见上，「DS」已词汇化；且它被 `DS-common.md`、下发指令、路由注册表、memory 与三个项目引用，成本远高于收益。若将来执行端不再是 DeepSeek，重新评估。
- **框架与既有项目一次性全改**。放弃：项目仓不归框架会话写（`~/sim` 明确不碰），强行同步会越权。改为过渡期规矩 + 以实际文件名为准。

## 验收证据

改名后全仓 `grep CODEX` 只剩三类合法命中：`~/.codex/skills`（Codex 这个**工具**的路径，非角色）、`~/sim/CODEX.md`（sim 尚未改名的事实）、以及历史引文中被明确标注为旧措辞的那处。

`scripts/check-decisions.sh` 的证据链可达性覆盖改名后的全部引用；`git mv` 保留了文件历史。

**未验证**：节名统一后的门禁（任务须有 `## 独立审查` 节）**尚未实现**——本仓不持有任务文件，该门禁要落在项目侧。
